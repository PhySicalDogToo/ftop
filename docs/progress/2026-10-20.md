# 2026-10-20

## Upload and download process rankings — local implementation complete

- Added download and upload to the existing single process list, with four native
  badge switches in wide layouts and one More → Process ranking menu at every
  size. Narrow lists and rich strips retain the selected metric. Rates reserve
  fixed geometry; unavailable readings remain dashes and measured zero remains
  zero. Network rows do not imply a share of physical-interface traffic.
- Independent network candidates are folded into applications before truncation.
  Each mode has its own stabilized order. Network-only entries without usage data
  keep CPU/memory unavailable; bare PID reuse cannot attach an older process's
  usage. Mode changes and hiding processes discard old traffic immediately.
- The native card shows two pairs of figures and localized scope limitations:
  TCP/UDP socket activity includes local/proxy connections, TUN may expose both
  layers, and unobserved or short-lived connections can be missed. Collection is
  read-only and on demand; it does not change DNS, proxy settings or routing.
- Fixed a reference-review finding: the sixth optional module was outside the
  five-column control block. Width now follows the actual column count without
  shrinking glyphs. Regression checks include every disc, glyph, label, palette
  ring and shared hover/click area in both languages, closed and expanded.
- After the generation-cache refinement, `scripts/check.sh` passed strict
  formatting, warnings-as-errors build and two complete passes of 249 tests.
  Generated 137 native references. Reviewed the 44 process/control pictures and
  ten existing size references, then rechecked the corrected English/light and
  Chinese/dark control blocks; no remaining clipping or overlap was seen.
- The isolated native preview was dragged through regular, large, tall/narrow,
  wide/thin and micro forms. The real More menu exposed all four
  modes and successfully selected upload. This complements the offscreen geometry checks; it is not evidence of
  complete coverage of every application's network provider.
- Final packaged `probe --network --json` returned 18 candidates per direction,
  positive rates, valid ordering, finite/nonnegative values and explicitly unknown
  usage. Deep strict signature verification and plist lint passed. Final C passed
  20 ASan lifecycle cycles (leak detection disabled). Provider tests: 13 passed.
- Final normal 1 s cost, panel plus helper: CPU ranking 0.3–0.7%, download and
  upload 1.0–1.5% of one core, about 39–40 MiB top MEM in network mode. At 0.5 s,
  network peaks reached 12.8% without added traffic and 12.2% with loopback churn.
  The under-1% CPU reference target remains unmet. Short sequential samples do
  not isolate cache benefit or the cause of peaks. Memory stayed below 60 MB.
- A reliable native hidden-window performance measurement was not completed;
  the unverified attempted sample is excluded. Explicit provider stop/restart,
  liveness, stale frames and callback invalidation are tested/source-reviewed.
- Detailed sanitized cost, attribution, lifecycle and visual evidence is under

## Network ranking loading and 20-second return window

- Added typed loading state and localized “数据读取中” / “Reading data…” in the
  existing list/strip slot. Layout size does not change with status. Removed the
  idle process-card instruction; real errors and TUN scope remain.
- Added a queue-confined monotonic 20-second collection controller. Leaving for
  CPU/memory preserves the observer, rate baseline and fresh card rates. Returning
  cancels expiry; CPU/memory changes do not extend it. Expiry pushes stopped state
  immediately, and hidden/module-off/menu-bar-only/shutdown paths stop at once.
  Wake and cold return clear old UI traffic and establish a new baseline.
- Fixed a supported ten-second refresh edge: the rate delta accepts any finite
  positive elapsed interval, while completed native frames retain their existing
  six-second freshness check. No C/private API or privileged helper change.
- Final `scripts/check.sh` passed formatting, warnings-as-errors build and two
  complete 273-test runs. Targeted controller/provider/UI suites passed. A real
  production-sampler smoke observed initial readiness at 2.554 s, first-callback
  reuse after a three-second departure, expiry at 20.050 s, cold return, continued
  availability at ten-second refresh and explicit stop.
- Regenerated 181 native reference PNGs and README media. Reviewed all 28 new
  loading/card references and baseline representatives. Actual isolated-preview
  drags covered large, tall/narrow, wide/thin and regular forms; cold loading and
  subsequent rate display were observed in the real panel. Ranking placement
  remains below same-column basic information.
- One-second visible download cost including helper was 1.3–2.4% of one core
  (mean 1.8%), about 43.4–43.5 MiB summed top MEM. The existing under-1% CPU target
  remains unmet; no controlled regression or improvement claim is made.
- Built local `build/Ftop.app` 0.2.6, build 12; deep strict signature and plist
  checks passed. Evidence: `docs/evidence/2026-10-20-network-ranking-switch/`.
  Only owned temporary validation processes were stopped. No install, publication
  or modification of the user's network configuration.
