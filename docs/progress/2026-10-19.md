## Manual DNS editing

- Requested by the owner as stage two. Added an explicit editor under the DNS
  inspection menu, with automatic/custom mode and IPv4/IPv6 address validation.
  This changes the physical network service, persists across Wi-Fi SSIDs, and
  does not implement automatic rules.
- FtopSensors uses authorized SystemConfiguration preferences sessions and a
  nonblocking lock. It rechecks the location/service, connection fingerprint and
  full DNS baseline before changing only ServerAddresses, then commits, applies
  and rereads. Failures report known saved state without blind rollback.
- Saving is unavailable while the separate automatic DNS tool is detected.
  Opening/canceling/previewing does not write. Clash configuration is untouched;
  other resolver managers may continue to override effective DNS.
- The native editor keeps failed drafts, prevents closing during a save, and
  requires a fresh baseline after a conflict or uncertain result. App termination
  is vetoed during a save; updater installation is deferred while the editor
  is open. The existing root helper and monitor Scene are unchanged.
- Final `scripts/check.sh` passed: strict formatting, warnings-as-errors build,
  and both full test passes with 124 tests. Targeted UI tests passed (16), and
  the editor renderer produced twenty references in both languages/appearances.
  Inspected custom/automatic, compact error and saving states; no clipping seen.
- Opt-in read-only hardware smoke passed and identified the physical en0 target
  with a valid baseline. Packaged CLI before/after reads confirmed manual DNS
  unchanged. Sanitized evidence is in `docs/evidence/2026-10-19-dns-editing/`.
- `scripts/bundle.sh` produced the local `build/Ftop.app`; strict deep codesign
  and plist checks passed. The running installed app was not replaced or
  restarted. No native authorization prompt, real DNS save, installation or
  publication was performed.
- Not run: real authorization/commit/apply/resolver propagation, updated-app

## Wi-Fi DNS rules and Clash TUN cooperation

- Requested by the owner as stage three. Added editable exact SSID rules and an
  editable default for other identified Wi-Fi networks. Defaults are Office
  automatic and other Wi-Fi 114.114.114.114. Execution starts disabled/paused in
  every app session; saving rules pauses without changing service DNS.
- Sensors owns CoreWLAN/CoreLocation, retained native network authorization and
  serialized transactions. The App coordinator handles Wi-Fi/wake hints and a
  20-second fallback outside hardware sampling. Unknown names, uncertain
  adapters and non-Wi-Fi primary services do not apply the default rule.
- Existing DNS editing, app termination and updater installation share activity
  guards. Pause invalidates queued work immediately, including a pending
  permission continuation and the final reload after resolver propagation.
  After a successful write, the complete verified DNS configuration must still
  match before recording ownership. External changes stop reassertion across IP
  renewal; uncertain association reads cannot clear the conflict.
- Added a separately reviewed Clash Verge Rev/Mihomo cooperation plan. It keeps
  TUN, nodes and routing, wraps existing scripts without running their main
  functions, validates isolated candidates, privately backs up originals and
  reloads only the exact reviewed runtime digest. Changed configurations require
  review again. A stale DNS-restore snapshot is archived only after reload.
- Clash does not share ftop's advisory file lock; the review warns against
  editing, updating or reapplying profiles during Apply. Before/after checks do
  not make foreign writers atomic. Failures retain recovery backups and avoid
  blind rollback. The existing setuid helper remains unchanged.
- Generated 24 offscreen rule-window references in both languages/appearances,
  including compact running, blocked and authorization states. Inspected the
  narrow views and the Chinese default editor; no clipping seen. The monitor
  Scene and its adaptive geometry are unchanged.
- Real read-only Clash preparation succeeded against seven configuration files;
  the installed Mihomo kernel accepted the isolated candidate. No real review
  Apply, Clash reload, location/admin prompt or DNS save was performed.
- Final `scripts/check.sh` passed: strict format lint, warnings-as-errors build,
  and two full passes of 196 tests. The 27 targeted runtime/cooperation/Wi-Fi
  tests also passed after the final cancellation and ownership fixes.
- `scripts/bundle.sh` produced `build/Ftop.app`; strict deep codesign and plist
  checks passed. The packaged CLI read succeeded. Before/after comparison
  confirmed manual DNS and all seven existing Clash configuration files were
  unchanged. Sanitized evidence is in `docs/evidence/2026-10-19-dns-automation/`.
- The installed running app was not replaced, restarted or enabled. No install,
  publication, native prompts, real DNS write or Clash reload was performed.
  Live Wi-Fi round trips, native interaction, updated-app performance and the
